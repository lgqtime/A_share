# 动态参数融合实现计划

> **面向 AI 工作者：** 实现时遵循测试先行；不要修改定时任务的调度时点、页面参数读取路径或现有单窗口优化器命令语义。

**目标：** 每个已验证交易日保存 9、21、28 日窗口的优化快照，以最近连续 5 个验证日的原始总收益率计算 ReLU 截断后的线性夏普权重，并发布融合后的参数到原有当前参数文件。

**架构：** 新增独立融合协调器，复用现有 `rolling_parameter_optimizer.main()` 但为每个窗口使用独立缓存目录。协调器将窗口报告写入长期快照目录，在三组结果和严格五日历史完整时才原子发布兼容的日期参数文件与 `current.json`。每日运行器只改为调用该协调器，其他任务步骤、归档和页面读取保持原样。

**技术栈：** Python、pandas、numpy、unittest、现有滚动参数优化器。

## 验收标准

- 所有权重都来自连续 5 个不晚于目标日的实际验证交易日，计算只使用原始收益率、`ddof=1` 和线性归一化。
- KDJ 加权区间使用左 floor、右 ceil；全部可调区间通过现有范围校验。
- 当前参数只会在完整且校验通过的融合结果产生后更新；失败时保留上一份有效文件。
- 日常任务继续生成并归档原有 canonical 文件名；筛选界面无需改动即可加载融合参数。
- 同一窗口、同一日期的已有快照可复用，后续每日运行只需要补充缺失的窗口结果和收益记录。
